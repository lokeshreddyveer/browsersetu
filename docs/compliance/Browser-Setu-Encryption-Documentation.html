BROWSER SETU - APP ENCRYPTION DOCUMENTATION

Prepared 17 October 2026 for App Store Connect (App Encryption Documentation). This describes version 0.2.0 of the iPhone/iPad app (bundle ID com.browsersetu.ios) and the Mac app (bundle ID com.browsersetu.mac).

1. THE PRODUCT

Browser Setu is a consumer web browser for iPhone, iPad and Mac. It displays web pages with Apple's WebKit, stores bookmarks, history and settings on the user's own device, and can optionally keep those items in step between the user's own devices. It is published by Lokesh Reddy Veerabhadra and is sold or given away to the general public through the App Store, with no custom configuration, no customer-specific features and no server operated by the publisher.

2. WHERE ENCRYPTION IS USED

All cryptography in the app is performed by Apple's own libraries (Apple CryptoKit, Apple CommonCrypto, the Security framework and the Network framework). The app contains no cryptographic code of its own, no implementation of any algorithm, and no proprietary or non-standard algorithm.

2.1 Web traffic (HTTPS / TLS) - provided by the operating system

Pages are loaded by Apple's WebKit, which uses the operating system's TLS. The app does not change, replace or add to the algorithms. This use is the operating system's, not the app's.

2.2 Credentials at rest - provided by the operating system

Saved sign-ins and the sync passphrase are stored in the Apple Keychain (accessible only when the device is unlocked, not synced or exported). The Keychain's encryption is the operating system's.

2.3 Sealed backups and sync snapshots - standard algorithms, used by the app (in addition to the operating system)

When the user makes a backup file, or turns on iCloud sync, the data (bookmarks, settings, and for sync optionally open-tab addresses) is encrypted on the device before it is saved or uploaded:

  • Encryption: AES-256-GCM (Apple CryptoKit), 96-bit random nonce, 128-bit authentication tag; the file header is authenticated as additional data.
  • Key: a 256-bit key derived from a passphrase chosen by the user, using PBKDF2 with HMAC-SHA-256 (Apple CommonCrypto), a random 16-byte salt and 600,000 iterations.
  • Purpose: protecting the confidentiality and integrity of the user's own data in a file or in the user's own iCloud. The publisher cannot read it: the passphrase never leaves the device.
  • The keys and algorithms cannot be changed by the user or by any third party.

2.4 Pairing two of the user's own devices on the same network - standard algorithms, used by the app

To send links or files between the user's own devices, the app opens a TLS 1.2 connection using Apple's Network framework with the standard pre-shared-key cipher suite TLS_PSK_WITH_AES_128_GCM_SHA256. The pre-shared key is derived with HKDF-SHA-256 from a one-time code of 100 random bits that the user reads from one device and types on the other. The code expires after five minutes and the session ends after five failed attempts. No server is involved.

2.5 Hashing (not encryption)

SHA-256 (Apple CryptoKit) is used to check that a downloaded extension package or a saved page has not changed, and to make short fingerprints. No secret keys are involved.

2.6 What is NOT encrypted by the app

The browser's local database (SQLite) is not encrypted by the app; it relies on the operating system's file protection and the app sandbox.

3. WHAT THE APP DOES NOT DO

  • It does not use proprietary or non-standard encryption algorithms.
  • It does not provide a cryptographic API, library or tool to other programs. Web pages and web extensions only get the encryption already built into WebKit.
  • It is not designed or marketed for information security, VPN, network infrastructure, or for the primary purpose of encrypting data.
  • It does not allow the user to change encryption algorithms or key lengths.
  • It does not communicate with any server operated by the publisher.

4. THE PUBLISHER'S CLASSIFICATION (to be confirmed by the publisher)

  • Encryption functionality: standard, publicly specified algorithms (AES, HMAC-SHA-256, PBKDF2, HKDF, TLS) accessed through Apple's libraries, with symmetric keys longer than 64 bits (AES-256, AES-128), used to protect the user's own data and local connections.
  • Primary function: web browsing. Encryption is an ancillary function, not the primary function.
  • Distribution: mass market, general public, through the App Store.
  • Classification offered for review: mass-market encryption item, Export Control Classification Number 5D992.c, authorization type "mass market" (no licence required for most destinations), subject to the self-classification report that applies to such items.

    • This is the publisher's own assessment. Export classification is a legal determination and should be confirmed with an export adviser before reliance.
