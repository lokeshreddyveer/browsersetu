# Browser Setu 0.3.3 (build 11)

Mac: notarized, stapled DMG (replaces the build 10 file on the same release). iPhone/iPad: TestFlight build 11. Same version number, higher build number.

## Added since build 10
- **iPad has its own touch design:** a one-row toolbar, large tab chips, a redrawn tab overview, the iPhone's full menu in ⋮, panels docked beside the page, a scroll-away toolbar with a return pill, and external-keyboard shortcuts.
- **Library panels** (Bookmarks, History, Downloads): beside the page, as a tab, or as a floating card, chosen in Settings or the first-run setup; the Mac sidebar's Downloads button now opens the panel instead of swapping the tab list.
- **First-run setup explains every choice in plain words** and has a new step for where the panels open.
- **Two-step sign-ins:** a saved username is filled on the first step (silently when only one is saved), the password on the next step behind Touch ID or Face ID.
- Settings window: no system title; the panel's own header names the page. Rows in History are one line. Lists load before they show, so rows no longer appear loose and then regroup.

## Fixed
- iPad ⌘L and ⌘K did nothing (they opened the phone's floating panel); now they focus the address field.
- The floating card no longer leaves an empty area under a short list.
- `try!` regex initialisers replaced by a safe fallback; documented the startup stop and the plain-HTTP web-content setting; CI now runs the fuzz tests and the SBOM script.

## Checked
- Full Mac unit run: 574 passed, 7 failed. Six of the failures were timing and scale tests that took 15 to 25 minutes after about 500 earlier tests had left web views behind (opening 100 tabs took 25 minutes); each passed when run alone (opening 100 tabs took 0.5 seconds). The seventh, a check that the running app is sandboxed with the right entitlements, can only pass in a signed build and was not run signed.
- Earlier, 12 focused suites (login, username step, privacy, fuzz, shortcuts, layout, page versions, YouTube rules) passed.

## Not checked
- iPhone and iPad unit and UI tests; the iPad design on a real iPad with an external keyboard (Safari failed on that keyboard too, so the cause may be the iPad or keyboard); live sign-ins and YouTube; real two-device sync; VoiceOver; the signed-build sandbox test.
