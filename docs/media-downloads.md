# Streaming downloads (HLS and MPEG-DASH)

Phase 17 of the Downloads work. A stream playlist (`.m3u8` or `.mpd`) is shown to the person with its choices, and only what they choose is downloaded and joined into **one file** in the Downloads folder.

## What it does

1. **Add Download** (or the LinkGrabber) recognises an address ending in `.m3u8` or `.mpd`. The button becomes **Next…**. Nothing is fetched yet.
2. **Next…** fetches the playlist only (a few kilobytes) and shows: format, length, the video choices (resolution, bitrate, codec), the audio choices (language), and subtitles. The best video and its matching audio are pre-selected; subtitles are off.
3. **Download** reads the playlists of the chosen tracks, then fetches the chosen segments (three at a time), then joins them. Unchosen alternates are never requested.
4. The result is a file, never a folder of segments:
   - fragmented MP4 video/audio → one **MP4**, built by a passthrough `AVAssetExportSession` (no re-encoding). If the system cannot build it and there is a single stream, the joined fragmented MP4 is kept and the inspector says so;
   - MPEG-TS (a single stream) → one **.ts**, labelled "not an MP4" in the inspector;
   - WebVTT only → one **.vtt**; subtitles chosen *with* video are saved beside it as `Name.<language>.vtt`.
5. An existing file is never overwritten: the finished file takes another name if the name is taken.

## Not supported (and said so in the preview, never attempted)

| What | Why |
|---|---|
| Live and event streams (HLS playlist without `#EXT-X-ENDLIST`/`VOD`, DASH `type="dynamic"`) | The list of segments is still growing; a recording is a different feature |
| Encrypted segments (`AES-128`, `SAMPLE-AES`, any `#EXT-X-KEY` other than `METHOD=NONE`, `#EXT-X-SESSION-KEY`) | No key is ever fetched; nothing is decrypted |
| DRM (`ContentProtection` in DASH) | Never bypassed |
| DASH with several periods, `SegmentList`, `SegmentBase`, a timeline that repeats to the end of the period | Not implemented; refused with the reason |
| Segments that are neither fragmented MP4 (with an initialization segment), MPEG-TS, nor WebVTT | Refused |
| Audio and video in separate MPEG-TS streams | Cannot be combined without re-muxing |
| A playlist that points at another master playlist | Refused (no recursion) |

## Safety

* **Same network rules as every download**: the address check (also after the name is looked up), the redirect guard (no `https`→`http`, no redirect into the local network, loop and length limits), the check of where the connection really went, the proxy choice, no cookies, no credentials. Untrusted origins (scripts, extensions, automation) cannot start a fetch at all.
* **Only `http` and `https`** addresses are ever followed from a manifest, and a secure playlist cannot hand the download to an insecure address. `file:`, `data:`, `javascript:`, `ftp:` are refused.
* **Bounds**: playlist ≤ 2 MB, ≤ 200 000 lines, ≤ 20 000 segments per stream, ≤ 200 streams, URL ≤ 8 KB, XML depth ≤ 24, ≤ 100 000 elements, a segment ≤ 512 MB. A DASH document with a document-type declaration (the way entities and external loads are defined) is refused before it is parsed.
* **Signed addresses**: the segment addresses live only in the task's private folder (`plan.json`), never in the ledger, the event log, the diagnostics or a failure message.
* **Private tabs and the private LinkGrabber collection never open a media preview** or create a task.
* **Only folders this module made are ever deleted** (`<Downloads>/.Browser Setu Media/<profile>/<task id>/`).

## How it fits the rest

* One ledger, one coordinator, one scheduler. A stream is a task with protocol `media`; it takes a place in the same queue as every other download and honours the "downloads at once" limit. Segments take connections from the same `ConnectionBudget`.
* **Pause** stops the run and keeps the segments fetched (each is whole or absent). **Resume**, also after a relaunch, fetches only what is missing. **Cancel** deletes the working folder. A failure that can be retried keeps the segments; **Try Again** carries on from them. A working folder left behind by a crash is removed at launch.
* **Speed limit**: held *between* segments (after each one, for the time the limit calls for). It is not enforced inside a segment, so the engine does not declare the "enforces speed limit" capability.
* Segments are fetched through `URLSession`, which streams to a file: memory does not grow with the size of a segment.

## Tests

`Tests/Phase17MediaTests.swift` (parsers; original H.264/AAC media generated with `AVAssetWriter` and served by the fixture server; integration; security) and `Phase17PrerequisiteTests` in `Tests/Phase16LinkGrabberTests.swift`.

The test media is original and generated at test time. MPEG-TS support is tested for byte order only (no TS fixture that a player decodes was built), so TS playability is **not** verified.

# Finding media on a page (Phase 18)

**Library ▸ Find Downloadable Media** (or *Find Again* in the sheet) reads the page that is open, once, and lists what it finds. Finding is not downloading: nothing is fetched until you ask to look at one stream's qualities, and nothing is downloaded until you choose Download.

## How it works, and what WebKit does not offer

WebKit has **no supported way to watch a page's network requests** (there is no per-request callback for media; `WKNavigationDelegate` covers navigation, content rule lists can only block, and `WKURLSchemeHandler` is for custom schemes). So there is no "media detected while browsing" mode, and none is faked. Instead, a short read-only script runs in the browser's own script world (`WKContentWorld.defaultClient`) when asked. It reads, per `<video>`, `<audio>` and `<source>`: the address (`currentSrc`/`src`), declared `type`, `duration`, whether encrypted-media keys are attached, and whether it plays from a `blob:` address; and per `<a>`, the address if it ends in a media or playlist extension. It reads no form values, text, cookies or storage, installs no observer or timer, and does not touch playback. At most 2 000 elements are looked at and 200 results kept.

## Classification

| Found | Shown as | Download |
|---|---|---|
| `.mp4 .m4v .mov .webm .mkv …` or `video/*` | Video file | ordinary download (size checked when it starts) |
| `.mp3 .m4a .aac .ogg .flac …` or `audio/*` | Audio file | ordinary download |
| `.m3u8` / HLS mime | HLS stream | after you look at its qualities (Phase 17 engine) |
| `.mpd` / DASH mime | DASH stream | same |
| `blob:` / MediaSource | In-page stream | **not supported**: no file at an address; never hooked |
| Element with encrypted-media keys | Protected | **not supported**: never bypassed |
| `file:`, `javascript:`, `data:`, local-network address | — | refused with the reason |
| Element with no telling extension or type | Media (seen only) | offered as a file; not claimed supported until it is fetched |

A candidate says how far it is known: *Seen → Recognised → Choices available (inspected)*, or *Not supported / Sign-in needed / Could not be read / Out of date*. "Can download" is shown only for a recognised file or an inspected stream that has something downloadable.

## Qualities and tracks

Looking at a stream fetches its playlist only (never a segment) and lists what the playlist says: resolution, frame rate (`FRAME-RATE` / `frameRate`), advertised bitrate, codecs (named: H.264, HEVC, AAC-LC…), audio languages, subtitle languages. Bitrates are advertised, not measured. The default is the best quality the MP4 can hold (AV1/VP9 are chosen only if nothing else is, with a warning), the audio of your preferred language if there is one (else the stream's default), and subtitles only if you set a subtitle language. Combinations that cannot be joined into one file are named before anything is fetched. The size estimate is advertised bitrate × length, labelled as an estimate.

## Privacy and authorization

* Candidates belong to the profile and the tab context they were found in. A **private tab's list is in memory only, is never inspected or downloaded** from here (downloads live in the ordinary list, which a private tab must not touch), and is dropped when the last private tab closes.
* A stream whose playlist needs a sign-in is reported as *Sign-in needed*: your browser's session (cookies, headers) is **not** handed to a separate download. Direct files are fetched the same way (no cookies), so files that need a session fail with a clear message.
* Addresses may carry signed queries: they are used to inspect or download and are never displayed, logged or exported; the sheet shows a redacted form.
* Only `http`/`https`; local-network addresses are refused from page discovery (use Add Download for your own network).
* Results that arrive after you left the page are dropped; candidates from another page are marked *Out of date* and cannot be started.
* Adding to the **LinkGrabber** uses the same collection, identity and duplicate rules; one stream is one candidate, whatever its qualities.


# Advanced media discovery (DX-07)

Phase 18 reads the page once when asked. DX-07 adds a **watcher** so the list is ready and stays current, and keeps what the page's frames and players say about themselves. It extends the same candidate list and rules; there is no second discovery engine.

## What runs in the page

A short script runs in **every frame**, in the browser's own isolated script world (`WKContentWorld.defaultClient`, never the page's), injected as a `WKUserScript` at document start. It is event-driven: a media element's own events (`loadstart`, `loadedmetadata`, `durationchange`, `emptied`, `play`, `pause`, `ended`, `resize`), a `MutationObserver` for elements added or re-pointed, `popstate`/`hashchange`/`pageshow`/`visibilitychange`, and the page's Resource Timing entries for playlists and script-fetched media. Updates are coalesced (150 ms), capped (40 players per flush, 100 players per frame, 200 resources) and skipped while the page is hidden. It reads addresses, declared types, picture size, duration, track labels, poster and play state, and nothing else (no text, forms, cookies or storage). It does not touch playback.

Setting: **Watch pages for media** (Media on This Page ▸ footer), on by default; it applies to tabs opened afterwards. Private tabs are watched too, but their list is in memory only and never downloaded from here (unchanged from Phase 18).

## What the browser believes

* The frame's **origin and whether it is the main frame come from WebKit** (`WKFrameInfo`), never from the message. An `origin` in a message is ignored.
* A frame must have announced itself (`hello`) since the last committed navigation; the origin must still match what WebKit gave then. A late message from the page that was left is dropped. Each frame has a token made by the script in its isolated world, which tells two frames of one origin apart.
* Messages are validated and bounded before use (sizes, counts, finite numbers) and rate limited per tab (burst 60, 30 a second).
* A page cannot call the handler or read the script: it is registered for the isolated world only (checked by a live test from the page's world).

## What a candidate keeps

Provenance (tab, navigation, the players and frames, with their WebKit-reported origins), the method that found it (a source a player is playing now > a loaded playlist > a declared source > a link), a confidence (Confirmed / Likely / Possible), and only what was observed: picture size (quality label such as 720p, or "Audio only" when a loaded element has no picture), duration, poster, track languages, whether it is playing, and an expiry when the address states one. **One source is one item** however many players use it ("used by 2 players"); different sources are never merged by title, host or look.

## Classification

Declared type first, extension as weaker evidence: video, audio, HLS, DASH, subtitle, poster, stream segment, unrelated, unknown. A `.mp4` in an `<audio>` element, or in a video element that loaded with no picture, is audio. Subtitles, pictures and stream pieces are never offered as downloads on their own. `blob:`, MediaSource and encrypted-media elements are labelled and never downloaded (unchanged).

## Expiring addresses

Expiry is read only from parameters that state it: `Expires`/`exp`/`expire`/`expiry` (epoch seconds or milliseconds), AWS/Google `Date`+`Expires`, Azure `se`. An expired candidate cannot be started; **Find Again** re-reads the open page, and if the **same player** now plays an address of the same kind and (when both are known) the same length, the candidate is updated in place; a different length is treated as a different item. Signed queries are never shown, logged or exported.

## Limits that are WebKit's

* WebKit has no supported view of a page's network requests. A player that fetches media only through script into a MediaSource shows as an in-page stream; playlists it fetched appear through Resource Timing (cross-origin sizes are withheld).
* A sandboxed frame that may not run scripts never runs the watcher (WebKit starts it in the frame's blank first document, which is replaced). The main page counts its iframes, so the sheet says "N embedded frames cannot be looked into" instead of guessing. A closed shadow root hides its elements.
* A hidden or occluded page is not scanned; it is read when shown.


## DX-08: advanced HLS / DASH

**Model.** `MediaStream` gained optional fields (channels, role, forced, hdr, extra initialization segments, parts, notes, mirrors); `MediaSegment` gained exact timing (`ticks`/`scale`/`startTicks`), sequence numbers and an initialization-segment index; `MediaPlan` is version 2 and still reads version 1. `MediaTiming.swift` holds exact fractions and the timeline analysis (gaps/overlaps compared as fractions, tolerances derived from the manifest's own rounding, the AAC frame and the video frame).

**HLS.** Master playlists become a graph (variants point at their audio group). Duplicates are counted once; a line with an unclosed quote is skipped alone; a variant naming an undefined audio group is kept as carrying its own sound, with a warning; I-frame playlists and closed captions are classified and not offered; keys are classified (AES-128 and SAMPLE-AES/FairPlay/Widevine/PlayReady) and never fetched. Media playlists keep sequence numbers, discontinuity sequence, program date, byte ranges and several initialization segments. Not supported, said plainly: gaps, variables, partial updates, packed audio (.aac/.mp3), live.

**DASH.** Multi-period (a track must be in every period), SegmentTemplate (number, time, fixed duration, `endNumber`, negative repeat bounded by the next entry or the period end), SegmentList (with ranges), SegmentBase / single-file representations (fetched whole), BaseURL inheritance with alternates used on retries, roles, channel configuration (including Dolby masks), HDR from transfer characteristics, text tracks (WebVTT, TTML as a file; text inside MP4 is not extracted). Not supported: dynamic MPDs (DX-11), remote periods, WebM, DRM.

**Choosing.** `MediaManifest.select(_:)`: quality policy (auto, highest, lowest, explicit, at most N p, codec), audio languages (first is primary, others are added), subtitle languages, forced subtitles. An explicit quality stays authoritative unless fallback is allowed; a stand-in must be the same kind of stream, in the same audio group, at an equal or lower bitrate. A missing language is reported, never silently replaced.

**Fetching.** Each piece is validated by its first bytes (MP4 box types, TS sync bytes, WEBVTT, TTML) as well as status, range and size; a SHA-256 journal records every kept piece and is re-checked on resume (a changed file of the right size is fetched again); tracks are interleaved by progress; waits follow Retry-After or jitter; a host that fails 12 times in a row is left alone; 401/403/410 trigger a refresh instead of a retry.

**Expired links.** The manifest is read again from the address it came from (at most twice per run, reset by a person's own resume). The new links are used only if tracks, segment counts, lengths and byte ranges are identical and the hosts are ones the download already used. Otherwise the download stops with the reason and keeps its pieces.

**Output.** Parts of a track are placed end to end; tracks of one part keep their offsets to each other. Several audio tracks go into the one MP4 (language tag and three-letter code set); if the system's writer refuses, each extra track is exported as its own `.m4a` beside it. Subtitles are always sidecars: the system's passthrough export cannot write timed text from WebVTT, and nothing is generated. The result is checked for track counts, length (shorter than the playlist by more than its rounding allows is refused, not published), and sound/picture length and start. Full disk keeps the pieces and says so.

**Verified how.** Unit tests, assembly tests with real generated media, and live downloads against a local server; finished files are read by the system's reader and player and by `scripts/mp4_probe.py`, which shares no code with the app. Real third-party servers, hardware players other than AVFoundation, and the new picker controls (compiled, not clicked) are not verified.


## DX-09: websites and what they permit

`MediaProviders.swift` decides which site a page or embedded frame belongs to (exact host or dotted subdomain of a known domain; userinfo, trailing dots, lookalikes and non-ASCII hosts do not match), what the site permits (`MediaProviderCapabilities`: metadata, playback, direct/approved/API download, own-data export, account archive, authentication, restriction, official alternative), and one rule for the Download button (`canDownloadNow`). A provider's own media hosts are held to its rules whatever page they are found on, so generic discovery cannot be used to get around them.

**Per provider.** Vimeo: API download links through the owner's authorization (token per profile in the existing Keychain wrapper, sent only to the API host, no redirect followed; `download` array only, never playback `files`; links last 24 hours). TikTok: Data Portability status is read; the archive itself is not downloadable here (it needs a POST download the HTTP engine does not do). YouTube, Instagram, Facebook, X, Reddit: recognised and described; no download is offered, with the official route shown. Anything else: the generic path (DX-07 discovery, DX-08 downloads).

**Renewal.** A renewed source must be the same provider, profile, media id, source kind, size or checksum, quality and dimensions, on the same server or one the provider declares. A private tab never uses the account's token.

**Not verified.** No live provider call was made: provider answers are fixtures written from published documentation. The exact field names for Vimeo link expiry and TikTok statuses are not checked against the live APIs.


### DX-09 closure: what the windows do now

**Provider panel (media sheet).** For the page in front: the site's name, what it permits, and only the actions that work. Vimeo: *Authorize…* (an access token the person creates for their own account with scopes public, private and video_files; kept in this profile's Keychain, sent only to api.vimeo.com, never used in a private tab), *Resolve*, then one *Download* button per owner-enabled download link. Other recognised sites: the limitation and the site's official route, no Download. TikTok: *Export my TikTok data…*. A sign-in window is not built: it needs an app registered with the provider, and none is bundled.

**Operations.** `ProviderFlow` runs each lookup through `ProviderOperationState` (a move the machine does not allow is refused). A result is applied only if its operation is still the current one and the profile is unchanged; cancelling or replacing an operation makes any late answer harmless. A start is refused unless the operation is Ready for this page and profile and the source is one it produced. An expired link is renewed through the provider by the flow itself (at most twice) and only to the same file.

**Vimeo links.** Only the `download` array is used (links last 24 hours). `files` links (documented as non-expiring) and `play` links are playback links and are not used. API links redirect (HTTP 302) to a CDN: the download engine follows that through its own address checks, and the API token is never sent with the file request.

**TikTok Data Portability.** Add (`/v2/user/data/add/`), Check (`/check/`) and Download (`/download/`), all POST with a bearer token; `request_id` is an int64; statuses are pending, downloading (ready), expired (about four days after ready) and cancelled. The ZIP is streamed to a staging folder through the fetcher (no redirect, size limit 20 GB), checked to be a ZIP (header and end record; a JSON error served instead is reported as such), and saved through the normal Downloads lifecycle. The request is remembered across relaunch. It needs TikTok's approval of the app, a login-kit authorization with a portability scope, and an eligible account (currently the EEA and the UK); none of that can be switched on locally. Media links inside the archive are not extracted.

**Official routes.** Several export pages are sign-in gated and could not be checked (Instagram, Facebook, Google Takeout), X returned 402 and Reddit blocked automated reading, so the panel adds "the link needs you to sign in; it could not be checked" to each.

## Downloads on this page (category indicators)

`ResourceClassifier` (Shared/Downloads/Detection/ResourceDetection.swift) sorts a page's link addresses into categories by extension, well-known file names (Dockerfile, package.json, …), magnet/ed2k scheme, file-sharing host and provider watch-page shape; ambiguous endings (`.ts`) are low confidence, server-side page extensions are never files unless the page marks the link as a download, and `refine` lets a real response's type and disposition override the address. `BrowserModel.scheduleResourceScan` reads links through the existing `LinkPageExtractor` (new engine call `scanPageLinks`) at ~0.9 s, ~3 s and ~8 s after a page event and on request (Look Again); results are deduplicated by normalised address and capped at 500. Video and audio counts come from the media picker's own classification so the toolbar never promises more than the picker offers. Downloads go through `scheduleDownload(origin: .page)` (which refuses local-network addresses) or, for torrents and magnets, the link collection's consent preview. Video cards are discovered, not resolved: resolving formats happens on the video's own page through the provider flow. Not built yet: a resolver registry that inspects a card without opening it, a MutationObserver-driven index of cards in feeds, shadow-root media, and "Explore more" beyond re-reading the current links.

## Download-first video layer (options, consent, connector contract)

`VideoOptions` (Shared/Downloads/Media/VideoOptions.swift) lists what can be saved from a discovered item and why anything cannot: original file, source renditions named by their real height ("4K" only for a 2160p source), original audio, audio only (M4A) and MP3. Each option says whether the result is the source's own ("Source quality") or "Converted". `LocalEncoders` probes the system: M4A is available (AVFoundation); macOS ships an MP3 decoder but no encoder, so MP3 comes from LAME 3.100 (LGPL 2.1), vendored unmodified (encoder only) in `apps/apple/ThirdParty/lame` as the separate static-library target `MP3Lame`; the app links it, `MP3Encoder` (Shared/Downloads/MediaProcessing) decodes with AVFoundation, encodes in chunks, supports cancel, and validates the result. `VideoResolutionState` (discovered / analyzing / formats available / authorization required / unavailable) is derived from what is known, never from a domain name. The stream picker (`MediaAddView`) has a Save switch: Video with sound, or Audio only (M4A) — the stream's own audio, not re-encoded, written as `.m4a` and checked with the system reader and `scripts/mp4_probe.py`.

`MediaConsentStore` keeps scoped, revocable permissions per profile (once, this website, this profile) for page discovery, frame inspection, extended analysis, provider account use, local conversion and sending a page address to one named service; a private tab is never covered for an outside service. `DownloaderServiceConnector` / `ConnectorValidator` define the contract and the checks on a service's answer (same video, https, approved hosts, not expired, type matches, not an HTML page). **No service is enabled**: no public downloader website has a verified, documented integration, and private endpoints are not used. A download started from a page list in a private tab is now recorded as private in the ledger (`scheduleDownload(isPrivate:)`).

Not built: a direct file's audio extraction, MP3 encoding, a per-video Download sheet on every card (cards open their page; the stream picker and provider panel do the resolving), consent prompts in the UI, and any enabled external service.

### Per-video Download sheet (VideoDownloadSheet, VideoSaveOperation)

A Download button on each video entry opens the sheet: a direct file offers Original, Audio only (M4A) and MP3; a stream opens the existing quality picker; a provider video shows its status and opens its page. `VideoSaveOperation` adds no transfer code: the download is an ordinary coordinator task (private in the ledger for a private tab), and the audio is made from the finished file by the existing local media-processing service (M4A) or `MP3Encoder`. A second click starts nothing; Cancel stops both the download and the conversion; the file keeps its own ending when the name is edited. Converting asks for scoped consent (`MediaConsentStore`), listed with Revoke in Settings › Media. The popover's open state lives in the model (`resourcePopoverKey`), so a rescan that changes the chips cannot close it; `ResourcePopoverStateTests` pin that.

Provider videos: no download route is offered for YouTube (or other providers without a documented, permitted one); the sheet says so and the page opens. Building a YouTube extractor would mean reproducing its unofficial player interfaces and defeating its access checks, which this app does not do.

LGPL notes for LAME: the library is a separate target with its full source in the repository and no changes, so it can be replaced and the app relinked; a release must keep `ThirdParty/lame/COPYING`, `LICENSE` and `README.browsersetu.md` and offer that source.

## Capability-based resolution (no provider denylist)

Provider identity no longer blocks a download. `ProviderCatalog` has no per-provider "restricts its own media" flag, `MediaCandidate.canOpen` / `downloadSupported` no longer consult the provider, and `ProviderPolicy` is informational (it names the provider and its official route beside a candidate that cannot be downloaded). What decides is what the media is: a plain file or HLS/DASH stream is downloadable wherever it is found; protected (DRM) media, an in-page (blob) stream, an expired link, a stream that was not inspected or holds nothing downloadable, and an address on the local network (for a page-origin request) are not. Authentication is enforced by the server's own answer: the transfer carries no browser cookies or tokens, so media that needs a sign-in fails with the server's refusal rather than being fetched around it. `ProviderRestriction.providerPolicy` is now `.noRoute`: for a provider *page address* with no media in hand, this app has no resolver (only Vimeo's owner-enabled download links, PeerTube's public API, and TikTok's account export are implemented), so it says that, and opens the page, where whatever the player exposes in the clear is listed in Media on This Page. Retained on purpose: DRM, blob, expiry, local-network, consent and private-tab rules. Not built: a resolver that turns a provider's watch page into a file (YouTube, Instagram, Facebook, TikTok, X, Reddit), and documented external connectors (none verified).

## Normalized media sources (extractor → picker → engines)

`NormalizedMediaSource` (Shared/Downloads/Media/NormalizedMedia.swift) is the one description any extractor ends with: direct tracks (muxed, or separate picture and sound, with container, codecs, size, language, expiry) or a stream manifest. `validate()` accepts only accessible media (http/https, not a picture or page, not expired, not a local address unless the person typed it). `options()` lists only what can be made, each marked "Source quality" or "Converted", with the reason when something cannot (WebM cannot be joined or have audio taken by the system's media engine). Existing extractors feed it through `init?(authorized:)` (provider-authorized sources) and `init?(candidate:)` (what a page's player exposed). `SourceSaveOperation` carries out the choice with existing engines only: coordinator downloads, `MediaAssembler.combine` to join separate tracks, the stream engine for manifests, local processing / `MP3Encoder` for audio, then reads the result back. Provider identity plays no part. Verified by `DX08InteropTests` matrix (separate tracks → one MP4; direct with/without sound; sound → MP3; HLS → MP4, M4A, MP3; refused: no media, expired, picture, local address; every provider passes the same plain file). Not built: extractors that turn a watch page into media (YouTube, Instagram, TikTok, Facebook, X, Reddit), MPEG-DASH separate-representation and multi-language selection through this layer's UI (the stream picker handles those), WebM joining, expired-link renewal through this layer (renewal is in ProviderFlow for provider sources).

LAME is now a dynamic, replaceable `libmp3lame.dylib` in Contents/Frameworks (see ThirdParty/lame/README.browsersetu.md for the replace-and-re-sign route and what remains a distribution decision).

## External extractor, review fixes and the move out of the App Sandbox (Nov 8)

**Distribution decision (final):** Browser Setu ships only as a direct-download DMG: hardened runtime, Developer ID, notarized. The App Sandbox is off for the Mac and Direct app targets (`project.yml` generates their entitlements; the share extension stays sandboxed because macOS requires it). Kept: camera, microphone, calendars and iCloud key-value entitlements (hardened-runtime/capability keys, not sandbox keys). Removed: network, files.*, print, `temporary-exception.mach-lookup` (sandbox-only). Not changed: `SUEnableInstallerLauncherService` (Sparkle; harmless unsandboxed, unverified either way).

**External extractor** (`Shared/Downloads/Media/ExternalExtractor.swift`, UI in `VideoDownloadSheet.swift` `ExtractorLookupView`, Settings › Media › External extractor): off by default; the person chooses a program; the page address is passed after `--` with fixed arguments `--dump-single-json --no-playlist --no-warnings`; the child runs via `posix_spawn` in its own session (so a timeout or cancel ends the whole tree: SIGTERM, then SIGKILL after 2 s), stdin /dev/null, all other descriptors closed, environment `PATH=/usr/bin:/bin`, `LANG`, `HOME` only, output capped at 8 MB, 60 s limit, two at a time. The program must be owned by this person or root, not group/other-writable, with no ACL, in a folder (and ancestors, sticky folders aside) others cannot change. Consent (`.externalExtractor(<path|fingerprint>)`) is bound to that program's path and SHA-256 prefix: a changed or different program asks again, lookup refuses a program that changed after consent, and a private tab never runs it. The answer is parsed as the shape yt-dlp's JSON uses; numbers are range-checked, strings capped, `webpage_url` is required and must be on the asked site (same host, subdomain, or two names of one known provider; never a bare TLD or a shared public suffix), repeated format ids collapse, formats needing cookies/authorization headers or non-plain protocols are skipped with a reason, every address is checked like any other (http/https, no local network, not a picture or page, not expired). ### Release signing and notarization procedure for the media-tools package (to be run by the publisher, not done in this task)

Goal: a package that launches under Gatekeeper with the quarantine flag left on (BrowserSetu sets `LSFileQuarantineEnabled`, so everything it downloads is quarantined; properly signed and notarized code passes anyway).

1. Start from the pinned upstream onedir tree (`scripts/fetch-bundled-tools.sh`). Thin every universal Mach-O with `lipo -thin arm64` (and build a second x86_64 package if Intel is supported). Do not alter non-Mach-O files.
2. Sign inside-out with the Developer ID Application identity, hardened runtime, secure timestamp: `codesign --force --timestamp --options runtime -s "Developer ID Application: …" <file>` for every Mach-O (dylibs, `.so`, `Python`, then `Python.framework` contents, last the main `yt-dlp_macos`). `codesign` refuses to sign `Python.framework` as one bundle ("bundle format is ambiguous"); sign the files. Hardened runtime ran the tool in a scratch test with NO entitlements; if a future Python build needs `com.apple.security.cs.allow-unsigned-executable-memory` or `disable-library-validation`, add it per binary and re-test.
3. Zip with `ditto -c -k --keepParent`? No: zip the tree's CONTENTS (`cd tree && zip -qry ../yt-dlp-<ver>-arm64.zip .`) so the app's `unzip` produces exactly the signed tree. Notarize the zip with `xcrun notarytool submit … --wait`. A zip cannot be stapled; Gatekeeper uses the online ticket lookup at first launch. If offline first launch matters, ship a signed, notarized and stapled DMG instead and teach the installer to mount it (not built).
4. Compute the digest of the SIGNED tree: `python3 scripts/tree_digest.py <tree>` (the app's `treeDigest` is identical) and the zip SHA-256; write both, the zip size, the unpacked size, the architectures, and `"signaturePolicy": "teamID:X4MH29QNRS"` into `ThirdParty/<tool>/MANIFEST.json`, host the zip at an approved address, and ship the new manifest with the app. The digest therefore changes with every re-signing: regenerate it after signing, never before.
5. Acceptance on a clean Mac/user: install through the app, confirm `codesign --verify --strict` on every Mach-O, `codesign -dv` shows the Team ID and `flags=…(runtime)`, `spctl --assess --type execute -vv` says "Notarized Developer ID" (not yet confirmed for bare tools; if `spctl` rejects non-app Mach-O files, replace that check with `syspolicy_check distribution` or a launch test only), then run a lookup and a download. The installer already refuses to activate anything that fails any of these or does not start (`--version` must return the pinned version).

## DX-11 — Advanced file transfers: FTP, FTPS, SFTP, WebDAV, remote browsing, Metalink (2026-11-09)

**Architecture.** A remote file is an ordinary download task. `RemoteFileRunner` (like `RemoteZipRunner`) does only the protocol part and the coordinator owns everything else (queue, per-host limit, progress, pause, cancel, retry, scheduling, naming, staged publication, ledger, history, Finder, collections). New protocol id `.remoteFile` ("remote"); hooks mirror RemoteZip's in `DownloadCoordinator`. WebDAV files are plain https/http files for the HTTP engine; WebDAV only adds folder listing (PROPFIND) and a capability check.

**Protocols (no third-party code in the DMG; the Mac build is a direct notarized DMG, not the App Store).**
- **SFTP:** the system's OpenSSH client (`/usr/bin/ssh -s … sftp`) carries the connection (key exchange, host keys, password / key / agent sign-in, keep-alive); `SFTPSession`/`SFTPWire` speak SFTP v3 on its pipes (listing in batches, symlinks resolved, pipelined reads of 32 KiB × 64 in flight, `pwrite` at offsets, resume from the contiguous prefix). The app keeps its own `known_hosts` per profile and passes `StrictHostKeyChecking=yes`; the first key is shown (SHA-256 fingerprint) and trusted by the person, a changed key is refused and needs an explicit "Replace Trusted Key". Password/passphrase reach ssh through a 0600 temporary askpass file removed as soon as the connection is up or fails. `-F /dev/null`, no forwarding, no `~/.ssh/config`.
- **FTP / FTPS:** the system's `curl` (credentials on stdin, never argv; `--ftp-skip-pasv-ip`; no proxy from the environment). MLSD with a LIST fallback, resume with `-C`, explicit TLS (`--ssl-reqd`) or implicit (port 990); a server certificate the system does not trust is refused until the person has seen its SHA-256 fingerprint and trusted it for that server only (`--cacert`, hostname still checked). A server without REST restarts the file from zero (once).
- **WebDAV:** PROPFIND Depth 1 through `MediaFetcher.exchange` (same address checks, redirect guard and proxy as every download); hrefs outside the folder, on other hosts, with `..`/slashes are ignored; Digest-only servers are reported honestly; Basic over http is never sent (credentialed WebDAV is https, riding a website account).
- **Metalink:** Metalink 4 and 3.0 parsed (priority/preference order, SHA-256 used, other hashes noted); a document opened from a file, a page link or the address bar is summarised and asked about, then added as ordinary downloads (several files: one collection). Sources are used together only when the document gives a SHA-256 AND every source is public; otherwise one at a time.

**Integration.** Address bar: `ftp://`, `ftps://`, `sftp://`, `dav(s)://` and `.meta4/.metalink` addresses open Remote Files / the Metalink question instead of navigating (also when a suggestion is selected). Page links: a click on such a link does the same; a link a page navigates to by itself does nothing, and a page-supplied address only fills the form (never connects). Downloads → Collect → "Remote Files…". Saved servers in the sheet (metadata in `remote-connections.json`; secrets in the Keychain, never in the file, a record or a collection's source; private tabs keep nothing).

**Collections.** Choosing files and folders reads the folders (bounded: 24 levels, 5,000 folders, 20,000 files, loop detection by the server's canonical path), keeps the structure under the collection's folder, and records each file's identity (`path#0`), so asking again for the same place downloads only what is new.

**Verified.** Real OpenSSH server (SFTP: key and passphrase sign-in, listing with Unicode/symlinks/permission errors, 6 MB byte-exact download at ~170 MB/s on loopback, resume, unknown/changed host key, wrong key); FTP/FTPS fixture server (plain, anonymous, LIST fallback, no-REST, cut connection + resume, explicit FTPS untrusted certificate refused then trusted); WebDAV fixture (listing, Unicode, Basic auth, hostile hrefs, XXE); coordinator integration (task record, no credentials in the record, free name for a second copy, folder structure, pause/resume, relaunch record has no secret); Metalink 3/4 and import rules. Native click-throughs in the real app: `sftp://` typed in the address bar → host-key question → browse → enter folder → select → Download → four files complete in Downloads (and byte-compared by hand: `dataset.bin` identical); asking again → "already downloaded"; a page's FTP link → Remote Files opens without connecting → wrong password explained → right password → file completes.

**Not done / limits.** No upload, sync or remote delete (out of scope). SFTP password sign-in is only exercised through the key-passphrase path (a non-root sshd cannot check passwords). FTP/SFTP do not use the browser's HTTP proxy; no per-transfer speed limit for them. One `ssh`/`curl` per file (deliberate; the per-host connection limit applies). SHA-256 only is verified for Metalink (SHA-512-only documents are noted, not checked). No third-party real-world FTP/SFTP/WebDAV server (Nextcloud, vsftpd…) was available: all servers are the system OpenSSH or small test servers. The native test for a Metalink link click is not written (unit-tested). FTP symbolic links are skipped (the listing does not say what they point at).

### DX-11 addendum — upload and delete, never sync (2026-11-09)

Approved after closure: the remote browser can upload files and delete items on SFTP, FTP/FTPS and WebDAV servers. There is no sync, no mirroring and no background comparison.

- Both act only on items the person chose, in a normal tab. A private tab cannot change a server at all: no question is asked.
- Every change is confirmed first, naming the exact items, the connection and the server, and the folder. The default button is Cancel. Uploads say that a file with the same name is kept, not replaced.
- Uploads never replace: SFTP writes a hidden temporary file with an exclusive create and renames it into place (checked against the size first); WebDAV sends `If-None-Match: *`; FTP refuses an existing name. A cancelled or failed upload leaves no file and no hidden file.
- Delete plans the whole job before it starts and counts files and folders. A link is removed as a link and never followed, so what it points at is untouched. Folders are removed deepest first. Errors are said plainly (not found, permission denied).
- Same trust and credential rules as downloads (host keys, saved passwords in the Keychain, user-trusted certificates, proxy).
- Found while testing: SFTP uploads wrote packets from several tasks at once and a packet larger than the pipe's atomic size could be interleaved, dropping the connection; writes are now serialized. The result sentence ("kept as they were (already there)", "Deleted n items") was being cleared by the folder refresh that followed; the refresh now keeps it.
- Tests: `RemoteChangeTests` (3 tests: SFTP against the real OpenSSH server, FTP and WebDAV, and the model's confirmations) pass. Not covered by a native UI click-through. The full 59-test consolidated suite was not rerun after these changes.

## DX-12 — Developer downloads, artifact repositories, AI models, datasets and cloud storage (2026-11-09)

One capability layer (`Shared/Downloads/Providers/`) recognises an address, lists what is there, and hands the chosen files to the ordinary HTTP engine, queue and collections. It has no queue, transfer code or storage of its own.

**What it covers**
- GitHub: releases (all, latest, one tag, one asset link), source archives of a tag/branch, Actions run artifacts. Public repositories need no account and use the public asset links; private ones use the API asset URL with `Accept: application/octet-stream`. Checksums are shown only when GitHub states one (the asset `digest`) or a checksum file in the same release names the file (`SHA256SUMS`, `*.sha256`, `checksums.txt`); signature files are saved and said to be unverified. A recommendation (macOS + this Mac's processor, or universal) is made only when exactly one file fits; otherwise the sheet says why there is none.
- Hugging Face models and datasets: the revision is resolved to a commit and every file is addressed at that commit; the tree is read across pages (a `Link: rel=next` is followed only on the service's own origin); LFS files carry the LFS object id as a SHA-256, plain git files only a size; a file that is only a Git LFS pointer is never kept; gated repositories say so and are not worked around; rate limits (`Retry-After`, `x-ratelimit-*`) are reported with the wait.
- Cloud storage over plain HTTPS: S3-compatible listings (`ListObjectsV2`, including Google Cloud Storage's XML API), Azure Blob containers opened with a SAS address, and any single signed address (presigned S3/GCS, SAS, CloudFront). Signed addresses are shown with their secret parts hidden, an expired one is reported as expired and never retried.
- Entry points: Downloads → Collect → "Repositories & Models…" (prefilled from the current page when it is one of these), and a page right-click item "Download Files from This Page…" that appears only on such pages. Ordinary websites are never claimed and the address bar is untouched.

**Rules that were kept**
- Tokens live only in the Keychain-backed account store, are attached by the account router for the exact host, https only, `.user` origin only, never for a private tab; they are dropped when a service redirects to another origin or port, and never appear in an address, the ledger or a log. Only the (non-secret) `Accept` header is saved with a task, so a restart asks for the file and not for its description.
- Private tabs cannot use this feature at all (no tokens, no collections).
- A service-supplied name or path that climbs, is absolute, empty or doubled is dropped; special characters are encoded in addresses.
- A file whose length is not the length the service stated is deleted; with a stated SHA-256 the engine's checksum check applies.
- Large sets: collections are split at 1000 files; a file already at its place with the stated size is skipped on a second run (the Downloads history is bounded, so the collection's own record is not enough); requests are paced; when a service answers 429 the batch stops, says so, and a second run adds only the rest; free space is checked before anything starts; at most 50 000 files are listed per address and a sub-folder address reaches the rest.

**Not done / blocked**
- Google Drive, OneDrive and Dropbox need an app registration with each company (OAuth client ids and review) that cannot be made from here; nothing in this feature claims to support them from a generic link.
- AWS SigV4 with the person's own keys is not implemented. Public buckets, presigned links and SAS addresses work; a design for short-lived credentials (SSO / STS) is the next step, not permanent keys.
- GitLab, Maven, PyPI, npm and OCI registries are not implemented (their plain file links already work as ordinary downloads).
- Xet-backed Hugging Face files are fetched through the service's normal `resolve` redirect (documented as working for plain HTTP clients); no Xet client is bundled, so there is no chunk-level deduplication or parallel Xet reconstruction.
- A signed address is saved with its task like any download address until the record is cleared (the engine's ledger keeps the query); it is redacted everywhere it is shown.
- Throughput of very many tiny files is bounded by the existing per-task engine (see the measured numbers in the report).
