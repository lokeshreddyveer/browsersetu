## 4. Path and dependency risks

1. **Source-reading tests** are the main hazard: a moved file makes them fail with "no such file", not a compile error. Mitigation: before each batch, `grep` the batch's file names in `Tests/`, `iOSTests/`, `scripts/`, `docs/`, and update the strings in the same batch; verify with those test classes.
2. **BrowserModel / TabController extensions**: many files are `extension BrowserModel` or `extension TabController` (flagged in the CSV). They compile unchanged wherever they live (same module), so folder moves cannot break them, but they show the real coupling: `App/Model/BrowserModel.swift` (4,103 lines) is the hub. Do not try to decouple during the move.
3. **Existing `Shared/Privacy/` (12 files)** overlaps the new Privacy sub-folders. Plan: sort those 12 into the same sub-folders in the same batch.
4. **`Shared/Downloads` loose files** (`DownloadCoordinator*.swift`, `DownloadQueue/Stats/Toast/Flight`, `FileRules`, `FileTools`, `PieceDownload`) belong to Downloads functionally but sit at `Shared/` root. They are mapped into `Downloads/{Coordination,Browser,Files,HTTP}`. This is the only change that touches the Downloads tree, and only by adding files.
5. **Debug/Release conditional code** (`DIRECT_BUILD`, `#if os`) is per-file and unaffected; the CSV lists guards for reference.
6. **Merge conflicts / parallel work**: the 399 uncommitted entries mean any other editor or agent working in `Shared/` during the move would collide. No agents should run during a batch.
